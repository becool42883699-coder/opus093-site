# T-rex株式会社 ホームページ(目で追う恐竜ヒーロー)

claude.ai のチャットで作った1ページのホームページを、Claude Code で続きを作業できるように分解したもの。
見た目の正解は `reference/trex-home-single-file.html`(チャットで公開していた最終版。全アセット埋め込みの1ファイル)。

> **この `opus093-site/trex-dino/` について(2026-10-18)**
> ユーザーから受け取ったのは `reference/` の1ファイル版と README / CLAUDE.md / .gitignore だけで、
> **`tools/`(目のアセットを作り直す Python パイプライン)は含まれていない**。
> `site/` は1ファイル版から埋め込み画像と描画コードを取り出して、下の構成どおりに分け直したもの
> (`dino-renderer.js` のシェーダーと `geo.js` の値はチャット版と同一)。目まわりを作り直す時は、
> ユーザーの手元の `tools/` で `build.py` を回し、出力を `site/assets` と `site/dino/geo.js` に上書きする。
> 親リポジトリ(Next.js)のビルド・lint の対象外(`eslint.config.mjs` で無視済み)。

## 構成

```
site/                    ← 公開するもの(静的サイト)
  index.html             ページ本体(HTML/CSS/ページ側JS。恐竜の動きの制御もここ)
  dino/dino-renderer.js  WebGL描画(シェーダー+テクスチャ設定)。window.TrexDino.makeRenderer を公開
  dino/geo.js            目の座標・可動範囲など(tools/build.py が生成。手で編集しない)
  assets/                base.webp(目を抜いた背景)/ eye-atlas.png / mask-atlas.png / fallback.webp
tools/                   ← 目のアセットを元画像から作り直すPythonパイプライン
  src/original.png       元のキャラ画像(1672×941)
  build.py               これ1本で全工程を実行し site/ に書き出す
  remove_text.py         画像左側に焼き込まれた社名ロゴ・キャッチを消す(HTMLの文字で載せ直しているため)
  contour.py             両目のまぶた輪郭(手で置いたスプライン制御点)
  build_eyes.py          白目の埋め直し・黒目テクスチャ・光の点・光沢・まぶた陰影・可動範囲
  pack_atlas.py          テクスチャをアトラス化(WebGL1のテクスチャユニット8枚制限対策)
  preview/               固定ポーズで描画して品質確認する道具
reference/               チャット版の最終成果物
```

## はじめに

Windowsでは `start-claude-code.bat` をダブルクリックすると、Gitリポジトリ化して Claude Code が起動する。

## 動かし方

`file://` で開くと WebGL がテクスチャを読めない(クロスオリジン扱い)。必ずローカルサーバーで開く。

```
npx serve site          # または: python -m http.server 8000 --directory site
```

## 目のアセットを作り直すとき

```
cd tools
pip install -r requirements.txt
python -m playwright install chromium
python build.py                    # site/assets と site/dino/geo.js を更新
python preview/render_poses.py     # preview/out/ に各ポーズの画像を出力
```

**目まわりを変更したら毎回 render_poses.py を回し、`eyes_original.png` と `eyes_rest.png` を拡大して見比べ、
他の全ポーズ(下右・下左・右・左・左上・右上・まばたき)も目視確認すること。**
チャットでは「確認したつもりで実機で崩れていた」ことが何度もあった。静止状態は元画像とほぼ同一が合格基準。

## 描画の仕組み(dino-renderer.js のシェーダー)

1. 頭の動き: 顔の奥行きを楕円体で近似し、画像を歪ませて首振りに見せる(`disp()`)。文字・爪・台は動かない範囲に設定済み。背景が単色なので継ぎ目は見えない
2. 背景: `base.webp`(黒目を抜いて白目を埋めた画像)
3. 目ごとに:
   - まぶた輪郭マスク(mask-atlas の R)で切り抜き
   - 黒目テクスチャを視線方向へずらす。眼球が球である前提で、端に寄るほど楕円につぶす
   - まぶたの影(mask-atlas の G)を黒目にも反映。静止位置との比で掛けるので、静止時は元の絵と一致する
   - 光の点(eye-atlas の hl 領域 R)は黒目と一緒に動く。角膜の光沢(同 G)は動かない
   - まばたき: 上まぶたが8割下り、下まぶたが2割上がる。まぶたの色は geo の lid
4. 動きの制御は index.html の createDino(): 目と頭は臨界減衰バネ(目 ω=26・頭 ω=4.2)、固視微動、
   ランダムまばたき(大きな視線移動のときは出やすい)、操作がないときのキョロキョロ、初回だけ目を開けて社名→こちらを見る演出

## 調整ポイント

| 変えたいもの | 場所 |
|---|---|
| 黒目の動く量 | index.html の `draw(..., .85)` の最後の引数(可動範囲に対する倍率) |
| 目・頭の速さ | index.html の `spring(..., 26/4.2, dt)` |
| 頭の振れ幅 | dino-renderer.js の `disp()` 内 `uHead*4.` と `uHead*16.` |
| まばたきの間隔・速さ | index.html の `blinkAmt()` |
| まぶた輪郭 | tools/contour.py の制御点 → build.py |
| 黒目の形 | tools/build_eyes.py の `AX`(実測した半径。黒目は少し縦長の楕円) |
| まぶた際の影の濃さ | tools/build_eyes.py の `ao=(1-0.55*...)*(1-0.12*...)*(1-0.15*...)` |

## チャットでの経緯・やってはいけないこと

- **黒目の静止位置は元の絵のまま**(少し寄り目でこちらを見ている)。白目の中央に置く案は試したが「目がおかしい」と却下された
- **まぶた輪郭を自動検出に戻さない**。自動だと黒目が接する部分がギザギザになり、黒目が動くと白目が欠けて見えた。手で引いた輪郭が正解
- **元の絵の画素はできるだけ描き替えない**。作り直すのは「黒目が動いた後に見える白目」と「まぶたに隠れていた黒目の端」だけ。広く描き替えたら「質感が落ちた」と言われた
- **黒目の大きさは実測値を使う**。真円・大きめで切り出すと白目まで含んでしまい、動かしたときに白いフチやもやが出た
- 右目の黒目の左側は、元の絵ではまぶたの帯に隠れて使えない。きれいな右側を左右反転して補っている。反転は光沢・光の点を消した後に行うこと(先にやると斑点が写る)
- 光の点の検出は狭く(明度232以上・彩度55未満)。広くすると周りの光沢まで巻き込んで灰色ににじむ
- テクスチャは4枚まで(base / eye-atlas / mask-atlas / 列データ)。WebGL1は最低保証が8ユニットなのでアトラスにまとめてある
- eye-atlas はアルファ事前乗算でアップロード、mask-atlas はしない(R/Gにデータが入っているため)

## ヒーロー以下のデザイン(2026-10-18 作り直し2回目)

経緯: 1回目(ステッカーの札・金属の線・角丸の黒いカード・線画アイコン・流れる帯)は
「全体的に普通。安っぽいところが多い」と言われた。**テンプレっぽさの元になるので、これらは戻さないこと。**
2回目は「スタジオの広告」の作り。文字の大きさ・余白・細い罫線で見せる。

- **面**: 青(ヒーローのスタジオ)/黒(ヘルメット #08090b)/白 の3つ。
  並びは ヒーロー(青)→事業(青)→施工実績(黒)→エリア(青・照明つき `.studio`)→会社(白)→採用(黒)→問い合わせ(青・照明つき)→フッター(黒)。
  `.studio` は背景だけでなく `color:#fff` も持つ(付け忘れて文字が濃紺になったことがある)。
- **見出し行 `.shead`**: 「(01) SERVICE ──── 事業内容」。欧文は Archivo の細幅(`--cond`、font-stretch 72%)。
  その下に和文の大見出し `.h2`(700・palt)。**行は `<span class="ln"><span>…</span></span>` で手で切る**
  (自動の折り返しだと「ます。」だけ次の行に落ちた)。
- **事業**: 「直す。/変える。/駆けつける。」の巨大な動詞(既存のコピー「直す、変える、駆けつける。」を3事業に割り当てた)
  + 事業名・英名・本文・相談する。マウスを乗せると行全体にヘルメットの黒い光沢が左から満ちる(`.srow::before` の clip-path、hover できる端末だけ)。
  クラス名は `.srow`(`.row` だとフッターの `.ft .row` とぶつかる)。
- **施工実績**: 荷台換装の3枚を「01 Before / 02 Process / 03 After」の1本の流れに、残り3枚は「そのほかの施工」。
  写真は下から幕が開く(`[data-ph]` の li を IO で見て、中の `.shot` を clip。clip した要素自身は交差判定が来ないため)。
  **スマホは横にめくる帯**(scroll-snap、1枚 80%)。縦スワイプはページが動くこと・横スワイプで帯が動くことを確認済み。
- **エリア**: 路線図のように 福岡県 ― 北九州(拠点・シアンの波紋)― 山口県。線は左右に伸びて現れる。

- **動き**: `[data-rv]` フェードアップ / `[data-ln]` 行マスクのせり上がり / `[data-ph]` 写真の幕。
  すべて `html.js`(<head> のインラインで付与)の時だけ隠す。JS 無効・reduced-motion では最初から見える。
  reduced-motion では `.in` の規則の方が詳細度が高いので、上書きは `.in` 付きのセレクタも並べること(路線図の線がこれで動いていた)。
