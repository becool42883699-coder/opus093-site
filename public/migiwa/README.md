**本文の地は `.62`。読書中の海は「記録の1枚」＝止まった絵で、しかも
`#stage` は `position:fixed`。** 動く背景に文字を置く話ではなく、
固定された1枚の上を文字が通過していくだけなので、地は思ったより開けられる。
実測（地のいちばん明るい砂に対して）:

| 地の濃さ | 本文 p | 一覧 dd | 見出し h2 | 8.5pxラベル |
|---|---|---|---|---|
| `.945`（前） | 13.6 | 12.1 | 16.6 | 5.4 |
| `.62`（現在） | 11.1 | 10.0 | 13.3 | 7.3 |
| `0`（全透過） | 6.8 | 6.2 | 8.0 | 3.4 |

全透過でも本文は 6.8:1 ある。効いてくるのは 8.5px の欧文ラベルだけなので、
本文の中のラベルだけ `--hud`（.60）から `.80` へ持ち上げてある（計器側は触らない）。
**ここを動かすときは必ず `measure-sheet.mjs` で測り直すこと。見た目で決めない。**

リンク検査は必ず `out/` に対して行う。`public/` を配ると `/becool/` が
無いので、生きているリンクまで404に見える。

**文字のコントラストはCSSの色を見ても分からない。** 3Dの上に乗るので、
背景は毎フレーム変わる絵になる。`measure-contrast.mjs` は各文字の
**外側 2〜9px の帯**を背景とみなして測る。矩形の中の画素を使うと、
白文字のアンチエイリアスを背景と誤認して、地色が暗い場面でも 1.1:1 と出る。

**この環境は約1fps（SwiftShader）。** 潜航は smoothDamp で追従するので、
スクロール位置を変えたあと収束を待つには「フレームが進んだうえで値が
動いていない」ことを条件にする。値だけ見ると同じフレームを2回読んで
「止まった」と誤判定する。

`--tier=high` を付けないと、検証機は hardwareConcurrency が小さいため
必ず low ティアになり、high 側にしかない経路(水面の映り込み)が
一度も動かないまま「通った」ことになる。

`verify.mjs` は**ページの隣をそのまま一時ディレクトリへ配る**。
`index.html` と `vendor/` だけ置くと本文の写真が 404 になり、しかも
遅延読み込みなのでそこまで送るスクロールをした時だけ落ちる
——「デスクトップは通るのにモバイルだけ console エラー2件」という
分かりにくい出方をした。

**「動いていない」ことを測るときは、必ず差分の位置も出す。**
`scripts/degrade.mjs` は reduced-motion の2枚が一致しない時に
差分の画素数と外接矩形を出す。合否だけだと原因の当て推量になり、
実際に魚を止めたあとも一致せずもう1周した（残っていたのは
被写界深度のピントの寄りだった）。

**「静止しているか」を秒で待たない。フレームで待つ。**
この環境は1〜4fps なので、3秒待つのは実ブラウザの 0.05〜0.2 秒に
しかならない。スクロールで飛んだ直後の収束(数フレーム)を
「動き続けている」と誤検出する。`degrade.mjs` は
`__diag.frames` が 40 進むのを待ってから1枚目、24 進んでから2枚目を撮る。
測りたいのは「収束したあと静止しているか」であって「常に静止しているか」ではない。

## 退避の3経路（毎回ここまで確認する）

```
node scripts/degrade.mjs
```

| 経路 | 合格の中身 |
|---|---|
| `prefers-reduced-motion: reduce` | 3.5秒あけた2枚が**完全一致**（差分0画素）。水面と汀の両方で。`timeScale` 0 / 汀線 d=0・θ=0・ずれ0 |
| JavaScript 無効 | 本文 15,024字・h2 11本・リンク7本が読める。**620vhの空白が0に畳まれている**。名乗りが `<noscript>` の静的な見出しとして出る |
| WebGL2 非対応 | 上端に案内、空白0、本文全部 |

**reduced-motion は「演出を止める」ではなく「1フレーム目で完成している」。**
一次遅れが1つでも残ると、海が止まっているのに何かだけが寄り続ける。
窓口は `ease1(k, dt)` と `lag1(t)` の2つだけで、reduced では
係数1・時定数0を返す。**新しく追従を書くときも必ずこの2つを通す**
（`Math.min(1, dt*k)` を直接書かない）。魚だけは時計が2つに割れていて、
位置と姿勢は `timeScale`、出入りの濃度は実時間（濃度まで止めると
alpha が 0 のまま一匹も出てこない。reduced では濃度も即座に当てる）。

**JS無効で畳むのは `html:not(.js)`。** `data-nogl` は JS が立てる属性なので
JS無効では絶対に立たない。`#hud` だけ消すと 620vh の空白（実測5233px）が
残り、本文の前に6画面ぶんの黒が挟まる。空白・暗幕・粒子・boot を畳んだうえで、
`#hud` ごと消える名乗りを `<noscript>` の中に静的に置き直す。

## 潜り終わりの受け渡し — 汀線(ていせん)

海から本文へ渡るところを、フェードではなく**幾何**で繋いでいる。

- ピッチ θ の透視投影では、無限に広がる床の消失線は必ず
  `ndc.y = -tan(θ)/tan(fov/2)` に出る。カメラの高さにも床までの距離にも
  依存しない。**θ=0 なら画面のちょうど垂直中央**。
- 本文シートの上端は、被覆率 c に対して `ndc.y = 2c-1`。
- よって **θ=0 かつ c=0.50 で、砂の消失線と本文の上端罫が同じ1本になる**。

時計は2本ある。**混ぜてはいけない。**

| | 何を駆動するか | 平滑 |
|---|---|---|
| `hpR` | 幾何（ピッチ / シートの見かけの位置 / 明線 / 汀の魚） | しない |
| `hp`  | 幾何でないもの（沈み込み / 計器の不透明度 / 時間の倍率） | 0.09秒 |

幾何を平滑化しないので、どんなスクロール速度でも線がずれない。

- 汀の窓 `cEff()` … `hpR` 0.36〜0.60 の間だけ、シートの**見かけの**上端を
  実スクロールの6%しか動かさない（`SEAM_K`）。実スクロールは1pxも奪わない。
  画面を約100px送るあいだ2本の線は4px以内に収まる。
  **6%を0%にしてはいけない** ―― 完全に止めるとスクロールの乗っ取りに読まれる。
- 窓は前後で非対称（下 0.14 / 上 0.10）。上側を 0.60 で閉じ切るのが要で、
  描画が止まる 0.62 で窓が開いたままだと、本文が数pxずれた位置で固まって戻らない。
- `measureSeam()` は **必ず `rect.top - seamDelta`** で測る。自分が当てている
  transform を引かないと、rect → hpR → seamDelta → rect の自己参照で発振する。
- `hpR ≥ 0.62` で描画を完全に停止し、`renderSettledFrame()` が**記録の1枚**を
  1回だけ描く。フリックで飛んだ人もゆっくり降りた人も、本文の裏に残る海は
  同じ1枚になる。呼ぶのは3箇所（凍った瞬間 / 本文中のリサイズ / 本文中の復帰）。
- `#content::before` が地色を **94.5%** に落としているので、その1枚が
  本文のあいだ 5.5% で残り続ける。動いていないから「記録」に読める。
- 本文の最後 `#outroOpen`（58vh）に入ると `rp` が立ち、**海が戻る**。
  `t` は1秒も進んでいないので、集光も魚も止めた場所から続く。

計器は消えず、**測る対象が深度から読了へ替わる**。
`#foot` は全画面幅で担い、`#ruler` は 1240px 以上でだけ目次になる
（それ未満は本文カラムと重なるので退役する。閾値は実測で決めた）。

## 魚 — 「間合い」

姿ではなく間合いを描く。**居場所はワールドに置き、カメラがその中を通り抜ける。**
群れをカメラの周りに置くと常に5m以上離れたままになり、警戒の半径（2.3m）に
一度も入らないので「反応」が一度も起きない（最初そう書いて、起きなかった）。

- 画面の中央に来るほど薄れる（周辺視）。床0.22・鈍り0.6秒は交渉不可。
- 逃げるときは半径方向ではなく**横**へ抜ける。必ず画面の端から出る。
- 刺激は距離ではなく**近づかれ方**（速さ `rush` / 正対 `look`）。
  ゆっくり降りた人の前では散らない。
- **止まると寄る。** ゲート3つ（カードを読んでいない / 汀の手前でない /
  スクロールが止まっている）は全部必須。
- 深いほどこちらを無視する。600m先で最も近くを通る1匹はこちらを見ない。
- `uFishWake` … マリンスノーを押しのける。**品質の梯子で切らない。**
  姿が見えなくても雪が割れれば「居る」と分かる、明るさに依存しない唯一の手段。
- 品質の梯子で落とすのは **近寄る距離だけ**。数も振る舞いも減らさない。
- 乱数は固定の種（`?fishSeed=` で上書き）。撮影と回帰が毎回同じ絵になる。
- `aPhase` は CPU で進め、必ず `timeScale` を掛ける。掛け忘れると
  凍った海の中で尾だけが振れ続け、「止まっている＝記録」が無効になる。

### 姿の描き方（3回踏んだので明文化する）

板は `PlaneGeometry(0.42, 0.20)`＝**2.1:1**。ここが全部の罠の元。

1. **形は uv ではなく「実寸の比」で書く。**
   `X = uv.x` / `Y = (uv.y - 0.5) * 0.4762`。両方「体長を1」とした同じ尺なので
   `length()` がそのまま円になる。uv.y をそのまま高さに使うと縦が 2.1 倍に
   潰れ、狙った 2:1 の胴が **4.3:1 の棒**になる。ぼかしが乗ると完全にただの線。
2. **胴と尾は必ず重ねる。** 尾柄（0.70〜0.80）に細い下限を残す。
   ここが 0 まで落ちると胴と尾が切り離れ、「魚1匹」ではなく「塊2つ」に見える。
3. **尾の外形を `tv*tv` で開かない。** 鰭が軸に貼りついたまま先端だけ広がり、
   上下の葉が細い筋になって燕の尾になる。`pow(tv, 0.8)` で早めに開かせる。
4. **`depthWrite:false` にしない。** 被写界深度は深度バッファを読むので、
   深度を書かない魚の画素では「魚の**奥**にある景色」のボケ量が当たる。
   汀の魚はカメラの手前 5〜8m に居るのに背後の砂（30m超）のボケが乗り、
   何をしても永久にぼやけたままになる。形は `discard` で抜いているので
   深度を書いても輪郭は濁らず、ついでに魚どうしの前後と、光条に対する
   シルエットも正しくなる。
5. **板に横分割を入れる。** 四隅4頂点だと頂点シェーダの
   `smoothstep(0.15, 1.0, uv.x)` が 0 と 1 でしか評価されず、曲線が消えて
   平行四辺形に傾くだけになる（＝「泳ぐ」ではなく「傾く」）。横10分割で胴がしなる。
