# あたり置き場

自分専用の公開ハブ。HTML一式のフォルダをブラウザにドラッグ&ドロップすると、数秒で確認用URLが発行されます。クライアントにはURLを渡すだけ。FTP作業はゼロになります。

- 最新URL: `https://atari-okiba.<あなたのサブドメイン>.workers.dev/p/<スラッグ>/`(更新しても変わりません)
- 過去版URL: `.../p/<スラッグ>/v/1/`, `/v/2/` …(アップロードのたびに自動採番)
- 案件ごとに閲覧パスワード(Basic認証)を設定可能。iPhone Safariでもそのまま開けます。

## 必要なもの

- [Node.js](https://nodejs.org/ja)(v20以上)
- Cloudflareアカウント(無料プランでOK)— <https://dash.cloudflare.com/sign-up> から作成

## セットアップ

3つのやり方があります。**A がいちばん簡単**です。

| | やり方 | あなたの作業 |
|---|---|---|
| **A** | 自動スクリプト | `sh setup.sh` を1回実行するだけ |
| **B** | GitHub Actions | GitHubの画面でシークレットを3つ登録してボタンを押すだけ(ターミナル不要) |
| **C** | 手動 | 下の6ステップをコピペ |

いずれの場合も、**R2の有効化だけは最初に一度、Cloudflareの画面で必要**です:
<https://dash.cloudflare.com/> → 左メニュー「R2」→ 案内に従って有効化。
(無料枠10GB。支払い情報の登録を求められることがありますが、無料枠内なら課金されません)

### A. 自動スクリプトで済ませる

```sh
sh setup.sh
```

ログイン → R2作成 → KV作成と設定反映 → 鍵の生成と設定 → デプロイまで自動で進みます。
途中でブラウザが開いたら「Allow」を押してください。最後に**管理画面の鍵が表示されるので必ず控えてください**
(この画面にしか出ません)。

### B. GitHub Actions でデプロイする(ターミナル不要)

1. Cloudflareで **APIトークン**を作る:
   <https://dash.cloudflare.com/profile/api-tokens> → 「Create Token」→ 「Edit Cloudflare Workers」テンプレート
   → 権限に **Workers R2 Storage: Edit** と **Workers KV Storage: Edit** も追加して作成
2. **アカウントID**を控える(ダッシュボード右側、またはURLの `dash.cloudflare.com/<ここ>`)
3. GitHubのリポジトリ → Settings → Secrets and variables → Actions → 「New repository secret」で3つ登録:

   | 名前 | 中身 |
   |---|---|
   | `CLOUDFLARE_API_TOKEN` | 手順1のトークン |
   | `CLOUDFLARE_ACCOUNT_ID` | 手順2のアカウントID |
   | `ATARI_ADMIN_TOKEN` | 管理画面の鍵(自分で決めた長いランダム文字列) |

4. Actions タブ →「あたり置き場をデプロイ」→ 「Run workflow」を押す

完了すると実行結果の画面に管理画面のURLが表示されます。以後も同じボタンで再デプロイできます。

### C. 手動で進める(コピペ)

すべてこのフォルダ(`atari-okiba/`)の中で実行します。

### 1. 依存パッケージを入れる

```sh
npm install
```

### 2. Cloudflareにログインする

```sh
npx wrangler login
```

ブラウザが開くので「Allow」を押します。サーバー等でブラウザが開けない場合は表示されるURLを手元のブラウザで開いてください。

### 3. R2(ファイル置き場)を有効化してバケットを作る

R2は最初に一度だけ、ダッシュボードでの有効化が必要です:
<https://dash.cloudflare.com/> → 左メニュー「R2」→ 案内に従って有効化(無料枠: 10GBストレージ/月。有効化時に支払い情報の登録を求められる場合がありますが、無料枠内なら課金されません)。

有効化できたら、バケットを作ります:

```sh
npx wrangler r2 bucket create atari-okiba-files
```

### 4. KV(案件メタ情報の置き場)を作る

```sh
npx wrangler kv namespace create META
```

実行すると次のような出力が出ます:

```
{ "kv_namespaces": [ { "binding": "META", "id": "ここに32桁の英数字" } ] }
```

この `id` の値をコピーして、`wrangler.jsonc` の `kv_namespaces` にある
`"id": "00000000000000000000000000000000"` を置き換えて保存します。

### 5. 管理画面のパスワード(ADMIN_TOKEN)を設定する

```sh
npx wrangler secret put ADMIN_TOKEN
```

と実行すると入力待ちになるので、**長いランダムな文字列**を貼り付けてEnter。
(例の作り方: `openssl rand -base64 24` をターミナルで実行した結果を使う)

この値が管理画面 `/admin` に入るためのパスワードになります。パスワード管理アプリ等に控えてください。

### 6. デプロイする

```sh
npx wrangler deploy
```

成功すると `https://atari-okiba.<あなたのサブドメイン>.workers.dev` というURLが表示されます。
初回は workers.dev のサブドメイン名を決めるよう案内されることがあります(画面の指示に従ってください)。

## 使い方

1. `https://…workers.dev/admin` をPCのブラウザで開く
2. ログイン画面が出るので、**管理トークン(ADMIN_TOKEN)** を入力して「ログイン」
   (ブラウザに保存しておけば次回から自動入力できます。トークンはページを開いている間だけ
   メモリに保持し、ブラウザには保存しないため、再読み込み時は再入力が必要です)
3. 「新規案件」でスラッグ(例: `acme-lp`)・表示名・閲覧パスワード(空欄なら誰でも閲覧可)を入れて作成
4. 案件カードの点線枠に**サイト一式のフォルダをそのままドロップ**(または「フォルダを選択」)
   → 1ファイルずつ順にアップロードされ、完了すると v1 として公開されます
5. 「コピー」ボタンで最新URLをコピーしてクライアントに送る
6. 修正版ができたら同じ場所に再ドロップ → v2 になり、**同じURLのまま**内容が新しくなります。
   過去の版は「履歴」の v1, v2 … リンクからいつでも見られます

閲覧パスワード付き案件をクライアントが開くと、ブラウザ標準のダイアログが出ます。
「ユーザー名は何でもよい(例: guest)、パスワードは伝えたもの」と案内してください。

## ローカルで試す(任意)

```sh
cp .dev.vars.example .dev.vars   # ADMIN_TOKENをローカル用の値に編集
npm run dev                      # http://localhost:8787 で起動
```

ローカル実行ではR2/KVはマシン内のシミュレーションが使われ、本番データには触りません。

## テストと型チェック

```sh
npm run check      # 型チェック(tsc)+ 自動テスト(vitest)をまとめて実行
```

## 困ったとき

| 症状 | 対処 |
|---|---|
| `/admin` が「ADMIN_TOKEN が未設定です」 | 手順5の `npx wrangler secret put ADMIN_TOKEN` を実行してから再デプロイ |
| デプロイ時に KV の id エラー | 手順4で `wrangler.jsonc` の `id` を実際の値に置き換えたか確認 |
| デプロイ時に R2 バケットが見つからない | 手順3のR2有効化とバケット作成を確認 |
| 「ログインできませんでした」と出る | ADMIN_TOKENを正確に貼り付け(前後の空白に注意)。変更した場合は再デプロイ不要ですぐ反映されます |
| アップロード後、別の端末で古い内容が見える | KVの伝播に最大1分ほどかかることがあります。少し待って再読み込み |

## 無料枠の目安

- Workers: 10万リクエスト/日、KV読み取り10万/日・書き込み1,000/日、R2 10GB
- 1回のアップロードで使うKV書き込みは2回(採番と確定)だけ。ファイル数の多いサイトでも安心です
- 閲覧1アクセスごとにKV読み取り1回+R2読み取り1〜2回。通常の確認用途なら無料枠に収まります

## 仕様の要点(詳細は DESIGN.md)

- 更新しても最新URLは変わらない(`/p/<スラッグ>/` は常に最新版)
- 過去版は `/p/<スラッグ>/v/<番号>/` でそのまま残る
- Content-Typeは拡張子から自動付与、フォルダURLは `index.html` を補完
- 公開サイト側の制約: サイト直下に `v/1/` のような「v+数字」フォルダがあるとバージョンURLと解釈されます
- 不要になった案件は各カードの「削除」ボタンで消せます(確認のためスラッグの入力を求められます)。
  全バージョンのファイルが消え、URLは開けなくなります。取り消しはできません

## セキュリティ運用メモ

- **スラッグに機微な情報を入れない**: 無認証で `/p/<スラッグ>/` を開くと、パスワード保護案件は
  認証ダイアログ(401)、存在しない案件は404を返します。この差でスラッグの総当たりにより
  「どの案件が存在するか」は分かります(中身は閲覧できません)。顧客名そのものをスラッグにせず、
  `acme-lp-7f3a` のようにランダムな接尾辞を付けると、存在の推測を防げます。
- **閲覧パスワードは確認用URLの簡易保護です**。強度が必要な機密資料の共有には向きません。
  推測されにくい十分な長さのパスワードを設定してください。
- **ADMIN_TOKENは長くランダムに**。これが管理画面の唯一の鍵です。漏れると全案件を操作されます。
- **管理トークンはブラウザに保存されません**(ページを開いている間だけメモリに保持)。
  これは、同じドメインで配信するクライアント成果物のJavaScriptからトークンを読めなくするための
  意図的な設計です。ブラウザのパスワード保存機能を使えば入力の手間は最小限で済みます。
